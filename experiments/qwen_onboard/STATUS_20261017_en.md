## 1. Deployed models

| Model | Form | Context | Decode | Status |
|---|---|---|---|---|
| **Qwen2.5-0.5B-Instruct** (primary) | INT4 G32 K-aligned weights + INT8 per-token KV | 192 tok | **~11.1 s/token** | Shipping config `mmap + GSC_ION=1`, board binary `qwen_engine_lmhead2_b2` |

## 2. Qwen highlights (Phase 6 → B2)

- **B2 dequant shipped on master**: INT4 nibble re-layout `nib[N][16] → nib16[16][N]` plus a
  contiguous `vle8` RVV kernel. Single-call throughput **1.75× (N=896) / 2.02× (N=4864)**;
  end-to-end CHAT 75-token prefill **304.5s → 219.6s (−28%)**,
  decode **16.25 → 10.98 s/token (−32%)**.
- **Two-stage LM head landed**: 1.84 MB centroid fp16 resident in ION (adaptive placement,
  falls back to DDR when headroom is low) + Stage2 span pread; head cost 0.5–0.7 s,
  host recall@1 reproduced 11/11.
- **INT8 KV cache**: context 48 → 192 (×4) within the same memory budget, bit-exact.
- **ION watchdog**: init-window coverage + atomic heartbeat; forced `_exit(1)` on hang,
  ION returns to zero with no leak, zero false kills on normal paths.
- **Correctness baseline**: 3-prompt NEXT 3/3 (2130 / 12095 / 99366), decode chain 2130→198→32,
  CHAT 75-token chain token-identical, TIU bit-exact counters all zero.
- **B-P0 weight prefetch closed**: `madvise` / `posix_fadvise(DONTNEED)` both return ENOSYS
  on this kernel; without a release mechanism the prefetch window collapses and all sweep
  points regress (+2.4 to +5.0 s/token). Archived; moving to B-P1.

## 3. Performance and hardware limits

| Metric | Value |
|---|---|
| Decode | 11.10–11.19 s/token (24 layers, SD-bound) |
| CHAT prefill, 35 tok | 101.7 s |
| CHAT prefill, 75 tok | 219.6 s |
| LM head | 0.5–0.7 s |
| Dequant throughput | 538 MB/s (N=896), 753 MB/s (N=4864) |

Hardware limits: SD sequential read ~20.2 MiB/s, ION carveout 28.1 MB, per-token weight
traffic ~201 MB. The implied decode floor is ~9.45 s; **11.1 s/token is the engineering
limit under these constraints**.

## 4. How to run

```sh
cd /data/qwen
# decode regression (mmap + GSC_ION=1 are engine defaults)
VERIFY=0 RSH=1 DECODE=1 DECODE_STEPS=6 PROFILE=1 ./qwen_engine_lmhead2_b2

# host-side chat
experiments/qwen_int4/.venv/bin/python3 chat_qwen.py "Hello"
```

## 5. Conclusion

Qwen2.5-0.5B-Instruct is fully deployed on CV1800B with INT4 weights, an INT8 KV cache,
and a two-stage LM head. It supports a 192-token context and interactive chat, with
bit-exact correctness and watchdog protection. Remaining headroom is bounded by SD
bandwidth and ION capacity; B-P1 (independent-thread pread double buffering) is the next
validation step.
