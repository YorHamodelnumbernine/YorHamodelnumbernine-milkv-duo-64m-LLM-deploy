## 4. 关键实现点

1. **M=seq 预填充**：r_opt 为 block-shared（每 K-block 跨全部 N tile 与全部 M 行收集 max），
   与 qwen_kal_ref M=seq 语义一致，保证 prompt3 边界 gap 可复现。
2. **LMEM 约束形状池**：M=3 最大 N-tile=896（31,456B），M=5/7=768（26,880B），
   精确匹配 {128,256,384,768,896}，避免 tile 宽 ≠ pool nshape 越界。
3. **合并 cmdbuf**：g2l(left)+g2l(right)+TIU matmul+l2g 单次提交，减半 submit 开销。
4. **流式 LM head**：8192 行 chunk 复用 layer 缓冲区，SD 22.2 MB/s 下覆盖 V=151936。
5. **CVI_RT_MemFlushEx / MemInvldEx**：range 级 cache 维护（DQ_OFF+P2_OFF 范围），
   替代全 buffer flush，VERIFY=1/0 均位精确一致。

## 5b. decode 上界口径（CEO 2026-08-13 裁定，正式 REPORT 锚点）

**Phase 5「跑一跑」基线**：decode 上界 = **SD 受限 ~11.6 s/token**（权重 201MB + LM head
136MB @ ~29MB/s 顺序读），与路径计算量（~200-500ms/token）无关——计算完全被 SD 掩盖。

| 口径 | 值 | 说明 |
|---|---|---|
| SD 权重（24×layerN_kal.bin） | 201.4MB @ ~29MB/s ≈ **6.9-9.2 s/token** | 实测 22.2MB/s → 9.18s（上板 dd） |
| LM head（embed_i8.bin 流式） | 136.1MB @ ~29MB/s ≈ **4.7 s/token** | V=151936，8192 行 chunk 流式 |
| **上界合计（理论）** | **≈ 11.6 s/token** | CEO 锚定值 |
| **M2 实测（VERIFY=0，15 token 平均）** | **14.55 s/token** | 含 TIU runs 6.26s + CPU/invld 1.4s + RVV dequant 0.31s + LM head 流式 4.7s，未完全与 SD 重叠 |
| 门禁 | ≈15.4 s/token | 实测 14.55 ≤ 门禁 ✓ |

- **对标准确性**：两路径（Path A 两遍法 / ps32 per-group）计算侧均 ~0.2-0.5 s/token，
  **勿用计算侧量级对标 decode 端到端**。端到端对标锚点 = SD 受限上界 11.6s +
  未重叠开销 = **Phase 5 实测 14.55s/token**。
- **Phase 6 真杠杆**（CEO 裁定，不在 Phase 5 兑现）：
  1. **LM head top-k 两段式**：先投影到聚类中心选 top-k 再全展开，把 136MB 流式读降
     1-2 数量级（当前 LM head 每 token 固定 ~4.7s）。
  2. **权重驻留/带宽**：INT8 KV / 频度热区缓存进 ION 5.16MB 余量、或双核 offload，
     压 SD 有效负载。
  3. 区域化 MemInvld / 合并 cmdbuf 已落地，余量优先投 LM head。
- **对标期望管理**：任何「上板 vs 设计」对标必须带口径前缀（如「TIU-only 4.17s/token」
  vs 「端到端 14.55s/token」vs 「SD 上界 11.6s/token」），避免偏差。
